# 第三方阅读统计同步

## 目标与范围

复用已有文件同步后端（首先覆盖 WebDAV，并保持共享 Provider 接口可用于其它后端），
不登录 Readest 也能合并各设备的阅读和听书统计。每个后端提供独立的
`syncStats` 开关，默认关闭。首次开启补传已有历史，之后仅上传新增或变化的记录。
统计面板继续从本地数据库展示，联网同步失败不得阻断本地统计查看。

第一版只合并历史，不提供跨设备删除或清空。沿用第三方文件同步的明文存储，
在开关说明中告知会同步阅读和听书历史。仅传统计所需书籍元信息和事件，不传凭据。

## 方案与约束

- 不同步 SQLite 数据库文件；使用书籍 hash、页码、开始时间组成的事件身份合并。
- 不写各设备共享的可变 stats.json；新增 `Readest/stats/v1/`，按设备目录写不可变
  分块文件，独立文件名避免并发覆盖。保留原书库和书籍文件布局。
- 同一事件重复读取不重复累计；时长只取更大值。旧历史、备份恢复、较早时间戳及
  已上传事件的时长增长均需同步，不能仅靠事件开始时间作增量游标。
- 每个同步目标单独保存上传确认和下载确认。目标身份包括后端、账号/服务端与
  根目录；换地址或目录后不能沿用旧目标的确认状态跳过首次同步。
- 只有远端 PUT 成功才确认本次事件快照；读取成功并落库后才确认分块。离线、
  崩溃和部分失败可重试；失败不推进确认状态。
- 遵循现有发送/接收策略。同步开关关闭、后端暂停或不可运行时不读写统计远端。
- 手动同步、书架自动同步、阅读记录持久化后的后台同步和统计面板打开均接入。
  统计同步独立于书籍是否仍在当前书库，听书事件通过同一本地统计库覆盖。
- 保留官方账号统计同步逻辑，文件通道独立工作。

## 本地确认与通道接口

采用每目标的快照确认表，不改变 KOReader 的事件表结构、不新增事件 outbox。
首次目标没有确认记录即回填全部历史；后续比较时长、页数和书籍元信息，只发送
目标尚未确认的快照。拉取成功时确认远端分块的值，不确认本地合并后的更大值，
使本地更长时长仍能在下一次上传中传播。上传成功但确认失败允许生成新分块重试，
读取同一事件的多个分块仍幂等。恢复设置导致设备 ID 重复时，随机文件名和按完整
路径记录的已读集合仍然避免覆盖和漏读。

唯一的预登记例外是本机新生成的随机分块路径：在 PUT 前登记为本机已知文件，
事件上传确认仍严格在 PUT 成功之后。这样上传成功但本地确认失败时，不会把自己的
旧快照重新当远端更新导入。PUT 失败的路径永不复用，事件仍待下次新路径重试。

新增三张附加表保存事件快照、书籍快照和已读分块；各事务与现有远端统计合并
共享数据库锁。新增方法：`getStatsFilePushBatch`、`ackStatsFilePush`、
`getSeenStatsFileChunkPaths`、`applyStatsFileChunk`。旧账号同步游标保持原样。

布局为 `Readest/stats/v1/<deviceId>/<uuid>.json`，分块包含 `v: 1`、`written_at`、
`books`、`events`。严格校验版本、字段类型、有限非负整数与大小，拒绝路径穿越。
损坏分块不记录已读；可读取的有效数据仍可合并，错误不得被显示为同步成功。

分层文件为 `statsFileLayout.ts`、`statsFileWire.ts`、`statsFileChannel.ts`、
`statsFileTarget.ts` 和 `statsFileSyncRunner.ts`，位于 `src/services/statistics/`。
UI 手动同步调用 `runFileStatsSyncForBackend(envConfig, kind, { provider, deviceId })`，
其余入口调用 `runFileStatsSyncForAllBackends(envConfig, { mode: 'full' | 'push' })`。
各后端调用串行化，后端间独立处理失败。统计失败不能误报为书库文件失败。

拉取逐块读取并提交，避免首次同步把全部历史解码到内存；书籍标题、作者分别以
`written_at` 与路径作为冲突顺序，空白字段不推进时钟，较晚到达的旧分块不能覆盖
较新名称，有效字段可以补齐空白字段。所有本地
写入与文件同步事务共享同一写入门，失败回滚不得带走并发记录的阅读事件。每块
处理前复查开关、目标和策略，中途关闭时停止后续读写。异常历史行不进入远端
分块；上传前用同一 wire 规则验证，保证接收端可读取。

## 实现与验证分工

1. 数据库与文件通道：增量确认、分块校验、幂等合并和重试测试。
2. 后端运行器与触发：设置类型、目标身份、各入口、并发串行化和故障隔离测试。
3. 设置 UI：共用表单增加开关，手动同步接入、默认关闭与保存测试。
4. 最终验证：合并各实现后运行统计/同步/UI 相关测试、类型与格式检查；完整检查
   通过后才报告完成。测试用内存 Provider 模拟多个设备、多个目标和失败重试，
   不使用用户的实际 WebDAV 写入数据。

测试先以缺失行为失败，再完成最小实现。关键断言包括：旧事件/开始时间为零、
重复同步不重复计时、已上传记录时长增长、多个目标隔离、换根目录重新回填、
发送与接收策略、开关关闭无数据库和远端访问、失败不确认、PUT 成功后本地确认
失败可重放、相同设备 ID 的两端并发、导入远端事件不循环回传、离线面板仍显示。

进度、验证结果和待办只记录在 [status.md](status.md)。本文件仅保存设计与约束。
